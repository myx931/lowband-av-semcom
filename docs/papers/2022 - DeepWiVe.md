# DeepWiVe 精读

## 核验后的定位

DeepWiVe 是较早的端到端无线视频 JSCC 系统，并用强化学习在 GOP 内动态分配带宽。它回答“有限信道符号应分给哪一帧”，为本课题的预算控制提供基线；它没有使用音频，也没有嘴部专门语义。[arXiv](https://arxiv.org/abs/2111.13034)；[DOI](https://doi.org/10.1109/JSAC.2022.3191354)

## 研究问题与假设

传统“视频压缩—信道编码—调制”在低信噪比和码率受限时出现悬崖效应。论文假设，联合学习从视频到信道符号的映射，并根据 GOP 内帧的重要性动态配置符号数，可以获得更平滑的质量退化和更高的感知质量。

## 系统链路与关键机制

系统以 $N=4$ 的 GOP 为决策单位。关键难点是编码端不知道经噪声信道后解码出的参考帧，因此不能像传统闭环编解码那样获得真实解码残差。DeepWiVe 的解码端用历史重建帧预测当前帧，编码端则基于可得信息学习发送用于修正预测的表示。

总带宽比定义为：

$$
\rho=\frac{k}{3HWN},
$$

其中 $k$ 是一个 GOP 的总信道使用数，$H,W$ 为分辨率，3 是 RGB 通道数。

带宽分配器采用 DQN。状态包含帧、预测残差、光流与信道噪声信息；动作把总预算离散分给 GOP 中各帧；奖励采用负对数失真，可理解为推动 PSNR 改善：

$$
r=-\log_{10}\mathcal{L}_{\text{dist}}.
$$

该分配是“帧级预算”，不是特征级 Top-K，因此只能作为上层资源调度参照。

## 实验设置与主要证据

- 数据：UCF101，按 0.8/0.1/0.1 划分训练、验证、测试。
- 信道：AWGN；训练 SNR 从 $[-5,20]$ dB 均匀采样。
- 训练硬件：RTX 2080 Ti；DQN 参数包括 $\gamma=0.99$、软更新 $\tau=0.005$、回放池 1000。
- 基线：H.264/H.265 + LDPC 与不同调制方式；指标为 PSNR 和 MS-SSIM。

在 $\rho=0.018$、SNR 3–6 dB 的报告区间，论文称相对 H.264+LDPC 最多提升约 4.72 dB PSNR 和 0.0462 MS-SSIM；相对 H.265 的 PSNR 较低，但平均 MS-SSIM 提升约 0.0058。优化分配相对均匀分配，在 $\rho=0.031$ 时提升约 0.67 dB/0.0008，在 $\rho=0.018$ 时约 0.99 dB/0.0023。

摘要/结论与细节段落对最大分配增益出现约 0.87 dB 与 0.99 dB 的表述差异；本笔记保留这一不一致，不据此给出唯一最大值。

## 局限与复现风险

- 只验证 AWGN，未覆盖突发分组丢失、衰落、CSI 估计误差和时延抖动。
- DQN 的离散动作空间随更细粒度分配快速膨胀，不宜直接用于每个嘴部 token。
- UCF101 不是以说话人脸和音画同步为核心的数据集。
- 与传统基线比较依赖具体 LDPC、调制和码率匹配方式；“优于 H.264”不能脱离工作点泛化。
- 未在本轮核验中定位到作者维护的官方实现。

## 对本课题的可复用模块

可将 GOP 级策略改为两层预算：

1. 上层依据 SNR、队列/时延与音频置信度，为当前帧分配残差 token 数 $K_t$。
2. 下层依据视觉重要性、预测不确定度和丢包风险挑选 Top-K。
3. 奖励同时包含口唇同步、身份/感知质量、信道使用与时延，而非仅像素失真。

DeepWiVe 最有价值的反例是：如果编码端和解码端对预测参考不一致，所谓“残差”会发生漂移。本课题必须说明音频基础嘴型在两端如何保持同一状态，或设计周期性锚点。

## 证据账本

- **论文事实**：GOP 内 DQN 分配、AWGN、UCF101、带宽比定义和上述消融数值来自论文。
- **跨文献推断**：DQN 可被更轻量、可微的预算网络替代，以适配实时嘴部 token。
- **待验证假设**：音频置信度与信道状态联合调度比只依赖 SNR 或残差幅度更稳健。
